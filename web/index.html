01

PRIMARY MODE

Wardriver

Separate Wi-Fi, BLE and LoRa views. Time-stamped observations, available receiver GPS, raw radio evidence and versioned sessions on microSD.

  • 2.4 GHz Wi-Fi AP observations
  • Passive BLE advertisements
  • Meshtastic, MeshCore or combined reception
  • Start, Stop + Save, and offline export
02

EVIDENCE VIEW

Recon

Passive Wi-Fi/BLE matches, category filters and readable evidence grades. Bounded buzzer alerts and optional SD rules help you choose what matters.

  • Matched results, with evidence and confidence
  • iBeacon, Remote ID and supported signatures
  • Vendor/name matches stay candidates
  • LoRa reception stops in Recon

A signature is evidence, not proof of a product, recording activity or identity. Randomized BLE addresses are temporary. Recon captures no Bluetooth connections and transmits no LoRa packets.

03 / CONNECT & INSTALL

Choose your hardware.
Install its firmware.

Choose the exact board and expansion fitted to your device.

Heltec: Expansion Kit V2 with V4-R8, 863–928 MHz radio hardware. Use the dedicated Heltec image.

Cardputer: Cardputer ADV with M5Stack Cap LoRa-1262 (U214), 868–923 MHz radio hardware and onboard GNSS. This target uses the physical keyboard and 240 × 135 landscape screen.

Use desktop Chrome or Edge over HTTPS and a USB data cable. Close serial monitors and other flashers. The installer identifies ESP32-S3; it cannot distinguish these boards or identify the fitted radio cap.

04 / FIRST SESSION

Card in. Mode selected.
Start observing.

  1. 1

    Prepare microSD

    Copy the supplied lora-tunnel folder to a FAT32 card. Rename config.example.json to config.json. The sample contains no credentials.

  2. 2

    Region, then Wardriver

    Select a region or Skip LoRa for Wi-Fi/BLE only. Start Drive begins a local session; missing GPS remains explicit.

  3. 3

    Save before shutdown

    Stop + Save closes the session. Settings → Power saves before sleep. Follow the selected board guide to wake or restart. Keep the native logs for export.

WiGLE CSV export needs fresh valid GPS and UTC; observations without them remain in native logs. WDGWars mesh ingestion remains a separate, unverified integration; decoded fields are preserved in native logs. Export rules ↗
